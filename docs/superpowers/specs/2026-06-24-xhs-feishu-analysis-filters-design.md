# 小红书飞书分析筛选回传设计

日期：2026-06-24

## 1. 背景

当前内容库筛选区把基础筛选、飞书同步状态、飞书分析字段混在一行。运营在飞书完成分析后，系统已经能把分析结果回传到本地，但回传字段没有完整成为内容库筛选选项，导致“分析完以后怎么用”不够直接。

本设计聚焦一个目标：

```text
飞书分析字段回传后，立刻成为内容库里可见、可选、可组合的业务筛选维度。
```

这不是要建设系统内产品库、标签管理或 AI 分类中心。飞书仍然是协作分析事实源，系统只把结构化结果接回来，用于筛选、展示和后续生产。

## 2. 目标

第一版完成以下能力：

1. 内容库新增独立的“飞书分析筛选”区域，和基础筛选区分开。
2. 飞书分析回传字段进入筛选选项，不在前端写死业务枚举。
3. 以下字段支持筛选：
   - 核心产品/服务。
   - 内容类型。
   - 可复用模型。
   - 内容利用方式。
   - 搜索属性。
4. 上述 5 个字段支持多选 OR：同一字段内命中任意选项即可。
5. 不同字段之间使用 AND：每个已选择字段都必须满足。
6. 重置按钮清空基础筛选和飞书分析筛选。
7. 后端查询真正按筛选条件返回结果，前端不做分页内假筛选。

## 3. 不做范围

第一版明确不做：

- 不建设系统内产品/服务主数据管理。
- 不让前端维护固定业务选项清单。
- 不从当前页数据临时聚合筛选选项。
- 不引入复杂规则引擎。
- 不修改小红书底层 SDK、签名或采集逻辑。
- 不改变飞书作为分析字段事实源的边界。
- 不做真实账号发布或自动运营策略调整。

## 4. 字段定义

内部字段使用稳定英文 key，避免中文字段名散落在前后端逻辑中。

| UI 文案 | 内部字段 | 数据形态 | 说明 |
| --- | --- | --- | --- |
| 核心产品/服务 | `core_product_service` | 单值或多值文本 | 产品、服务、主题、问题或内容对象。旧字段 `subject_object` 可作为兼容来源。 |
| 内容类型 | `content_type` | 单值文本 | 飞书侧分析出的内容形态。 |
| 可复用模型 | `reusable_model` | 多值文本 | 可复用的内容打法。旧字段 `reusable_models` 可作为兼容来源。 |
| 内容利用方式 | `content_usage` | 单值或多值文本 | 后续如何使用这条素材。旧字段 `reuse_value` 可作为兼容来源。 |
| 搜索属性 | `search_attribute` | 单值或多值文本 | 运营用于检索素材的属性，例如需求、场景、人群、关键词层级等。 |

兼容原则：

```text
新 UI 使用用户理解的中文文案；内部优先使用新字段名；已有数据库字段如果已经承载同义含义，则先做映射兼容，不强行迁移历史数据。
```

## 5. 筛选交互设计

### 5.1 页面分区

内容库顶部筛选拆成两个区域。

基础筛选区：

```text
[标题/正文/作者] [全部标签] [最新保存] [有素材] [有评论] [卡片/表格] [重置] [筛选]
```

飞书分析筛选区：

```text
飞书分析筛选
[飞书同步状态] [分析状态]
[核心产品/服务] [内容类型] [可复用模型]
[内容利用方式] [搜索属性]
```

用户影响：运营先用基础筛选缩小内容池，再用飞书分析维度找可用素材。界面上不再把“系统状态”和“业务分析结果”挤在同一行。

### 5.2 控件行为

- 5 个飞书分析字段使用多选 Select。
- Select 支持清空。
- 选项为空时控件仍显示，placeholder 表示“暂无可选项”。
- 飞书同步状态、分析状态可保留单选；如果实施中已有多选基础，也可以统一为多选，但第一版不强制。
- 筛选按钮触发请求，避免每次选择都刷新导致列表抖动。
- 重置按钮清空所有筛选状态并回到第一页。

### 5.3 筛选语义

同字段内多选 OR：

```text
核心产品/服务 = [AI 工具, 知识管理]
=> 命中 AI 工具 或 知识管理 的内容都返回。
```

不同字段之间 AND：

```text
核心产品/服务 = [AI 工具]
内容类型 = [教程]
=> 必须同时满足“AI 工具”和“教程”。
```

空字段不参与过滤。

## 6. 后端设计

### 6.1 查询参数

内容库列表接口扩展筛选参数，支持数组形式：

```text
analysis_status
feishu_push_status
core_product_service[]
content_type[]
reusable_model[]
content_usage[]
search_attribute[]
```

如果现有前端请求层不方便传数组，第一版可用逗号分隔字符串作为传输格式，但后端入口必须统一归一化成 list。

### 6.2 动态筛选选项

内容库需要返回或提供 filter options。选项来源是当前用户已有内容的飞书分析结果全量聚合，不受分页影响。

聚合规则：

- 只聚合当前用户有权限的数据。
- 去掉空值、纯空白值。
- 多值字段按列表元素拆分。
- 文本中如存在换行、中文分号、英文分号，可拆分为多个候选值。
- 选项按稳定顺序返回；优先按出现次数降序，再按名称排序，避免刷新时跳动。
- 不返回重复选项。

### 6.3 字段映射

为了兼容已存在实现，服务层建立字段映射：

```text
core_product_service <- core_product_service 或 subject_object
reusable_model       <- reusable_model 或 reusable_models
content_usage        <- content_usage 或 reuse_value
search_attribute     <- search_attribute
content_type         <- content_type
```

如果当前数据库模型尚未包含新字段，实施阶段优先选择最小可用改动：

1. 对已有同义字段直接复用。
2. 对确实不存在的字段补充模型与 Alembic 迁移。
3. 回传解析时把飞书字段写入对应字段。

## 7. 前端设计

### 7.1 类型扩展

内容库通用类型扩展：

- `ContentLibraryFilters` 支持分析字段数组。
- `ContentLibraryFilterOptions` 增加 5 个业务维度 options。
- `ContentLibraryController` 增加对应选中状态和 setter。

字段状态统一以 `string[]` 表示，避免单选字符串和多选数组混用。

### 7.2 Shell 布局

`ContentLibraryShell` 负责通用筛选 UI。设计上做轻量拆分：

- 基础筛选 Row 保持在第一个 Card。
- 飞书分析筛选独立 Card，只在 `adapter.capabilities.canFilterFeishuAnalysis` 为真时显示。
- 新增小的渲染 helper，避免一个 JSX 块继续膨胀。

### 7.3 XHS Adapter

小红书内容库 adapter 负责：

- 从后端拿动态 filter options。
- 把多选状态序列化为后端参数。
- 保持当前卡片和表格展示逻辑不变。

不在 adapter 中写死“核心产品/服务”等选项；adapter 只承接后端返回。

## 8. 回传链路影响

飞书到系统回传时，必须把新字段写入本地分析结果镜像。规则：

- 飞书是分析字段事实源。
- 飞书字段有值则覆盖本地。
- 飞书字段清空则本地同步清空。
- 回传成功后，动态筛选 options 下一次加载应能看到新值。

这保证运营在飞书完成分析后，不需要再到系统里维护一次标签。

## 9. 错误和空状态

- 如果飞书分析字段尚未回传，飞书分析筛选区域仍显示，控件 options 为空。
- 如果 filter options 请求失败，列表仍可加载；飞书分析筛选控件显示空 options，并在页面错误区提示“飞书分析筛选项加载失败”。
- 如果某个筛选组合没有结果，保持现有 Empty 状态，不额外报错。
- 如果后端收到未知筛选字段，忽略未知字段，不影响已知字段过滤。

## 10. 验证标准

### 10.1 后端

- 能把飞书回传的“核心产品/服务、内容类型、可复用模型、内容利用方式、搜索属性”保存到本地分析结果。
- filter options 来自全量已分析数据，不受分页影响。
- 同字段多选按 OR 过滤。
- 不同字段之间按 AND 过滤。
- 空值不进入 options。
- 字段清空后 options 和筛选结果能反映清空状态。

### 10.2 前端

- 内容库筛选区分为基础筛选和“飞书分析筛选”两个区域。
- “飞书分析筛选”区域包含 5 个业务筛选小框。
- 5 个业务筛选支持多选和清空。
- 重置清空所有筛选条件。
- 筛选请求携带多选值。
- 前端 build/typecheck 通过。

### 10.3 用户验收

运营完成飞书分析并回传后，可以直接在内容库：

1. 打开“飞书分析筛选”。
2. 在“核心产品/服务”看到回传过的产品/服务选项。
3. 多选两个产品/服务，结果命中任意一个。
4. 再选择一个内容类型，结果同时满足产品/服务和内容类型。
5. 点击重置，恢复默认内容库列表。

## 11. 用户影响

- 运营不用记住哪些飞书列对应系统筛选项，系统直接把分析结果变成可选条件。
- 内容库从“已采集素材列表”升级为“可按分析结论取用的素材池”。
- 飞书继续承担多人协作分析，不打断现有习惯。
- 系统不引入过重产品管理，第一版只解决最直接的素材筛选问题。
