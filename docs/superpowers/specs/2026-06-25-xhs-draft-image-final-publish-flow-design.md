## 1. 结论

本轮采用“前端任务化 + 后端多图 handoff”的方案，打通：

```text
内容库原始图文
  → 草稿工坊：改文字，保留并展示原始图片素材
  → 图片工坊：围绕当前草稿处理图片，选择最终发布图片
  → 发布中心：接收最终标题、正文、标签、最终图片
```

第一版不新增图片任务版本表，不做双向同步，不触发真实小红书发布。目标是先把运营最关心的“图文一直跟着任务走、最终发布图由用户明确选择”跑顺。

## 2. 当前代码判断

运营反馈成立，但不是“底层完全没传图”。当前系统已有部分链路：

1. 内容库创建草稿时，后端已经把来源笔记素材复制到草稿资产：`POST /drafts` 创建 `AiDraft` 后复制 `NoteAsset` 到 `DraftAsset`。
2. 草稿工坊送入图片工坊时，前端已经保存当前标题、正文、标签，并把草稿素材和来源笔记图组装成候选图上下文。
3. 图片工坊读取 sessionStorage 上下文后，能够展示“来自草稿”并自动带入候选图作为参考图。
4. 发布中心已有 `PublishAsset` 模型和资产展示/上传接口基础。

真正缺口是：

- 草稿工坊没有明显展示原图缩略图，用户感知为“图片没进草稿”。
- 图片工坊仍以通用 AI 图片工具为主，不像“当前草稿的图片处理任务”。
- 图片工坊没有“最终发布图片”选择区，用户无法从原图、上传图、AI 生成图中明确选择 1-N 张进入发布中心。
- 后端 `send-to-publish` 只支持单个 `asset_file_path`，不支持按顺序 handoff 多张最终图。

## 3. 用户目标

运营使用时应能完成：

1. 从内容库选择一篇对标笔记加入草稿工坊。
2. 在草稿工坊改标题、正文、标签，同时看到原笔记图片素材仍被保留。
3. 点击“送入图片工坊”，图片工坊明确显示正在处理哪篇草稿。
4. 在图片工坊中从以下来源选择最终发布图片：
   - 原笔记图 / 草稿素材；
   - 用户上传的客户产品图；
   - AI 生成图。
5. 勾选并排序 1-N 张最终图片。
6. 送入发布中心后，发布任务拿到同一套最终图文版本。

## 4. 非目标

本轮不做：

- 不新增 `image_tasks`、`image_versions` 等复杂图片任务表。
- 不做草稿工坊与图片工坊的双向自动同步。
- 不把图片工坊中的文字微调反向覆盖草稿工坊。
- 不改造 XHS SDK、签名、Cookie、真实发布策略。
- 不实现风控绕过、验证码绕过、高频自动化。
- 不自动真实发布，只创建发布中心待发布任务。
- 不接入 legacy TypeScript 系统。

## 5. 方案选择

### 5.1 采用方案

采用方案 A：前端任务化 + 后端支持多图 handoff。

核心：

- 草稿工坊显示来源图片素材。
- 图片工坊增加最终发布图片区。
- 后端 `send-to-publish` 兼容扩展 `asset_file_paths?: string[]`。
- 发布中心展示最终发布图片。

### 5.2 为什么不选轻量展示方案

只增强草稿和图片工坊展示，但不增加最终图片选择，会让链路“看起来顺”，但发布中心仍无法确认最终图组。运营反馈里的核心问题会复发。

### 5.3 为什么不选重型版本表方案

新增图片任务/版本表长期更完整，但会引入迁移、状态机、版本回滚、跨页面同步等复杂度。当前目标是先跑通最小闭环，避免把第一版拖成大重构。

## 6. 数据流设计

```text
内容库点击加入草稿
  → POST /drafts
  → 创建 AiDraft
  → 复制 NoteAsset 到 DraftAsset

草稿工坊点击送入图片工坊
  → PATCH /drafts/{id} 保存当前标题、正文、标签
  → GET /drafts/{id}/assets 获取草稿图片素材
  → 补充来源笔记图片候选
  → sessionStorage 保存 image studio draft context
  → 跳转 /platforms/xhs/image-studio?from=draft

图片工坊选择最终图片
  → 前端 selectedFinalImages 保存用户选择和顺序
  → POST /drafts/{id}/send-to-publish
     payload.asset_file_paths = selectedFinalImages.map(image.pathOrUrl)

后端创建发布任务
  → 创建 PublishJob
  → 按 asset_file_paths 顺序创建 PublishAsset[]

发布中心
  → GET /publish/jobs/{id}
  → GET /publish/jobs/{id}/assets
  → 展示最终标题、正文、标签和最终发布图片
```

## 7. 后端接口设计

### 7.1 扩展 DraftSendToPublishRequest

当前字段保留：

```python
asset_file_path: Optional[str]
```

新增字段：

```python
asset_file_paths: Optional[list[str]]
```

兼容规则：

1. 如果 `asset_file_paths` 非空，按数组顺序创建多个 `PublishAsset`。
2. 如果 `asset_file_paths` 为空但 `asset_file_path` 非空，沿用现有单图逻辑。
3. 如果两者都为空，沿用现有逻辑：复制草稿全部 `DraftAsset` 到 `PublishAsset`。
4. 过滤空字符串。
5. 去重但保留首次出现顺序。
6. 图片数量第一版不硬编码为 1 张；如需限制，由发布前检查或平台发布适配层处理。

### 7.2 路径校验规则

每个最终图片路径按以下规则处理：

- `/api/files/media/...`：复用现有 `_validate_handoff_asset_file_path`，只允许当前用户可访问的本地媒体文件。
- `http://...` / `https://...`：允许作为外链图片进入发布任务，真实上传失败由发布中心上传流程反馈。
- 其他协议或空值：拒绝或过滤，避免把不可发布路径写入发布资产。

### 7.3 PublishAsset 创建规则

对 `asset_file_paths`：

```text
for each path in normalized_asset_file_paths:
  create PublishAsset(
    publish_job_id=job.id,
    asset_type="image",
    file_path=path,
    upload_status="pending"
  )
```

排序由插入顺序表达。当前 `PublishAsset` 没有 `sort_order` 字段，第一版依赖 `id asc` 读取顺序；如后续发现排序强需求，可单独设计 `sort_order` 迁移。

## 8. 前端交互设计

### 8.1 草稿工坊：素材可视化

在草稿工坊当前“草稿内容”卡片中增加素材预览：

- 展示前 6 张图片缩略图。
- 显示素材总数。
- 显示素材类型：图片 / 视频。
- 图片为空时显示“这个草稿暂无来源图片，可在图片工坊上传参考图”。
- 提示文案：

```text
这些图片会随“送入图片工坊”一起带入，后续可选择最终发布图。
```

用户影响：运营能确认图片没有丢，不需要猜测系统是否只承接了文字。

### 8.2 图片工坊：当前草稿任务卡

强化已有“来自草稿”卡片，展示：

- 草稿 ID；
- 内部草稿名；
- 发布标题；
- 正文摘要，可展开；
- 标签；
- 候选图数量；
- 清除关联按钮。

文案从通用“图片工坊”偏向任务型：

```text
当前正在处理这篇草稿的图片。选择最终图片后，会连同草稿标题、正文、标签一起进入发布中心。
```

### 8.3 图片工坊：候选素材区

候选素材来源：

- `draft_asset`：草稿素材。
- `source_note`：来源笔记案例图。
- `manual`：用户上传图或手动输入 URL。
- `generated`：当前页面 AI 生成结果。

第一版不强制把 `generated` 写入 sessionStorage 上下文，只在图片工坊页面状态中加入最终图片候选。

每张候选图展示：

- 缩略图；
- 来源标签；
- “加入最终发布”按钮；
- 如果已加入，展示“已加入”。

### 8.4 图片工坊：最终发布图片区

新增核心区块：

```text
最终发布图片
已选择 N 张。发布中心将按当前顺序使用这些图片。
```

能力：

- 加入图片。
- 移除图片。
- 上移 / 下移排序。
- 清空选择。
- 显示数量。

默认行为：

- 从草稿进入时，如果有候选图，默认加入前 1 张候选图作为最终图片，降低用户首次操作成本。
- 用户可以删除后重新选择。

送发布中心前置校验：

- 必须存在草稿上下文。
- 必须至少选择 1 张最终图片。
- 如未选择，提示：

```text
请先选择至少 1 张最终发布图片。可以使用原图、上传图或 AI 生成图。
```

### 8.5 图片工坊：上传图进入候选

用户上传图片后：

- 继续进入现有用户图片资产列表。
- 同时可作为 `manual` 候选加入最终发布图片。
- 如果上传返回 `/api/files/media/...`，优先使用可发布的本地 media path。
- 如果只有外链 URL，则使用 URL。

### 8.6 图片工坊：AI 生成图进入候选

AI 生成成功后：

- 如果有 `generatedMediaPath`，优先将 `generatedMediaPath` 作为最终图片路径。
- 如果没有本地 media path，则使用生成结果 URL 作为候选。
- 提供按钮：

```text
加入最终发布图片
```

不要生成成功后自动送发布中心，避免用户误操作。

### 8.7 发布中心：最终图片展示

发布中心选中任务后展示：

- 标题改为“最终发布图片”。
- 展示 `PublishAsset` 缩略图。
- 显示图片数量。
- 保留现有上传状态、失败信息、重试入口。

第一版不改变真实发布按钮策略，不自动触发发布。

## 9. 版本流转规则

主流程单向推进：

```text
内容库原始素材 → 草稿工坊文字版本 → 图片工坊图片任务 → 发布中心最终版本
```

规则：

1. 草稿工坊负责主要文字编辑。
2. 图片工坊负责图片选择、生成、上传和最终图组确认。
3. 图片工坊第一版不反向覆盖草稿工坊。
4. 发布中心接收的是图片工坊确认后的最终图文版本。
5. 如果用户回草稿工坊重新改文字，需要重新送入图片工坊生成新的上下文。

## 10. 错误处理

### 10.1 草稿没有图片

不阻断进入图片工坊。提示：

```text
这个草稿暂无来源图片，可上传客户产品图或手动添加参考图继续。
```

### 10.2 sessionStorage 上下文过期

沿用现有提示：

```text
草稿上下文已过期，请从草稿工坊重新进入图片工坊。
```

### 10.3 最终图片为空

阻断送发布中心。提示用户先选择最终发布图片。

### 10.4 图片路径不可用

- 前端尽量只加入可渲染 URL 或 `/api/files/media/...`。
- 后端对非法本地路径返回 400。
- 外链图片允许进入发布任务，但真实上传失败由发布中心展示。

### 10.5 AI 生成失败

不清空草稿上下文和最终图片选择。提示：

```text
生成失败，草稿内容和已选图片已保留。请调整参考图或稍后重试。
```

## 11. 测试与验证标准

### 11.1 后端测试

必须覆盖：

1. 从有 `NoteAsset` 的来源笔记创建草稿后，`DraftAsset` 被复制。
2. `POST /drafts/{id}/send-to-publish` 传入 `asset_file_paths` 时，创建多个 `PublishAsset`。
3. 多图顺序与输入数组一致。
4. `asset_file_paths` 为空、但 `asset_file_path` 非空时，旧单图逻辑不破坏。
5. 两者都为空时，仍复制草稿资产。
6. 非法本地 media path 被拒绝。

### 11.2 前端验证

必须覆盖或手动验证：

1. 草稿工坊能看到来源图片缩略图。
2. 点击“送入图片工坊”后，图片工坊显示草稿标题、正文、标签、候选图。
3. 原图可以加入最终发布图片。
4. 上传图可以加入最终发布图片。
5. AI 生成图可以加入最终发布图片。
6. 未选择最终图片时不能送发布中心。
7. 选择多张最终图片后，发布中心能看到同样顺序的图片。
8. 前端 build/typecheck 通过。

### 11.3 安全验证

必须确认：

- 不触发真实小红书发布。
- 不修改 `apis/`、`xhs_utils/`、`static/` 底层 SDK/签名层。
- 不保存账号密码、Cookie、Token、API Key 到代码或文档。
