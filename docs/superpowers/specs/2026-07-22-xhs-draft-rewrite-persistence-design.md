# 小红书草稿工坊改写候选持久化设计

## 背景

当前草稿正文保存在 `ai_drafts`，但三种 AI 改写模式的候选只存在 React 页面状态中。关闭网站、刷新页面或重新进入草稿后，候选会丢失。用户确认本轮只恢复“当前草稿 + 最近一组 AI 改写候选”，不建设完整版本历史。

## 目标

- 当前草稿继续作为唯一可编辑正文。
- `safe`、`polish`、`seed` 三种模式各保存最近一个候选，合计最多三个。
- 同模式重新生成时覆盖该模式旧候选，不影响另外两种模式。
- 未采纳候选不覆盖当前草稿。
- 采纳候选时立即保存为当前草稿，关闭网站后仍可恢复。
- 放弃候选时同步删除持久化状态。
- 页面刷新、关闭重开和切换草稿后，从后端恢复候选。

## 非目标

- 不保存完整改写历史。
- 不保存标题候选和标签候选。
- 不改变真实模型调用、计费和任务审计规则。
- 不修改 XHS SDK、签名层、发布策略或 legacy 系统。
- 不把浏览器 `localStorage` 作为事实源。

## 数据设计

在 `ai_drafts` 增加可空 JSON 字段 `rewrite_candidates`。结构固定为：

```json
{
  "safe": {
    "title": "候选标题",
    "body": "候选正文",
    "tags": [{ "name": "标签" }],
    "generated_at": "2026-07-22T16:00:00"
  }
}
```

服务端只接受 `safe`、`polish`、`seed` 三个键。旧数据为 `NULL` 时按空对象处理。迁移只新增字段，不回填正文、不改写现有草稿。

## API 与流程

### 生成

1. 前端先调用现有草稿更新接口，保存当前编辑区。
2. 调用 `/api/ai/rewrite-note`，同时传递改写模式。
3. 服务端生成预览候选，写入当前草稿对应模式，覆盖该模式旧候选。
4. 前端只更新候选区，不覆盖编辑区。

### 恢复

选中草稿时调用 `GET /api/drafts/{draft_id}/rewrite-candidates`。切换草稿期间使用草稿 ID 防止晚到响应串到另一份草稿。

### 采纳

前端调用现有草稿更新接口保存候选的标题、正文和标签。保存成功后才更新编辑区，并提示“已采纳并保存”。候选继续保留，直到同模式重新生成或用户放弃。

### 放弃

调用 `DELETE /api/drafts/{draft_id}/rewrite-candidates/{mode}`。服务端删除该模式候选并返回剩余候选；其他模式和当前草稿不变。

## 风险控制

- 所有候选读取和删除都校验草稿所有权。
- 候选是服务端生成结果，客户端不能通过草稿更新接口任意写入候选 JSON。
- 生成完成后以新对象替换 JSON 字段，避免 SQLAlchemy 原地 JSON 变更未被追踪。
- 前端异步完成时校验当前草稿 ID，避免跨草稿污染。
- 草稿保存响应同时替换工作台列表项和当前编辑器状态，避免切换草稿后回显旧内容。
- 验证使用假模型客户端，不调用真实 Provider、不消耗真实额度。

## 验收标准

- 生成候选后刷新或关闭重开，候选仍存在。
- 三种模式各自只保留最近一个候选。
- 未点击采纳时，当前草稿正文保持不变。
- 点击采纳成功后重新进入，当前草稿显示采纳内容。
- 点击采纳后不刷新，切到另一草稿再切回，仍显示采纳内容。
- 放弃一个模式后重新进入，该模式为空，其他模式仍存在。
- 另一用户无法读取或删除该草稿候选。
- Alembic 临时数据库升级通过，后端聚焦测试和前端构建通过。
