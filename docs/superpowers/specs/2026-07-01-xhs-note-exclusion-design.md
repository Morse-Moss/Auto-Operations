# 小红书内容废弃库与重复分析拦截设计

日期：2026-07-01

## 1. 背景

当前内容库清理如果直接物理删除低分内容，会丢失系统记忆：下次采集再次命中同一条小红书笔记时，系统可能重新入库、重新同步飞书、重新触发分析公式或 AI 分析，造成重复污染和 token 浪费。

本设计把“删除低价值内容”改为“沉淀负样本并默认隐藏”：系统记住哪些笔记已经被运营判定为不值得使用，并在后续采集、同步、分析链路中主动跳过。

## 2. 目标

第一版完成以下能力：

1. 支持把小红书内容标记为废弃/排除，而不是直接物理删除。
2. 废弃记录进入独立排除清单，保留 `platform + platform_note_id`，用于后续采集拦截。
3. 内容库默认隐藏已废弃内容，运营日常只看到可用素材。
4. 后续采集再次遇到已废弃笔记时，跳过入库、飞书同步和分析。
5. 对飞书已有记录把 `分析状态` 标记为 `已废弃`，而不是删除记录，避免飞书侧失去上下文。
6. 支持本次清理规则：GEO 相关、方形/贴墙浴缸相关、非目标内容低分、浴缸低分内容。

## 3. 不做范围

第一版明确不做：

- 不做复杂废弃库 UI 管理台。
- 不做自动恢复流程。
- 不物理删除小红书笔记记录作为默认行为。
- 不修改小红书底层 SDK、签名或登录能力。
- 不改变飞书作为协作分析表的定位。
- 不让系统自动判断所有未来低分内容都必须废弃；本次只按明确规则批量处理。

## 4. 数据模型

新增表 `note_exclusions`，表示运营负样本/排除清单。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 主键。 |
| `user_id` | integer | 所属用户。 |
| `platform` | string | 平台，当前为 `xhs`。 |
| `platform_note_id` | string | 小红书平台笔记 ID，用于拦截重复采集。 |
| `note_id` | integer nullable | 本地内容库 note ID。物理记录保留时可关联，未来若清理 note 也不影响排除记忆。 |
| `source_url` | text | 原链接。 |
| `title` | text | 标题快照。 |
| `author_name` | text | 作者快照。 |
| `reason_code` | string | 机器可读原因。 |
| `reason_text` | text | 人类可读原因。 |
| `score` | float nullable | 废弃时的飞书评分。 |
| `rating` | string nullable | 废弃时的飞书评级。 |
| `external_record_id` | string nullable | 飞书记录 ID。 |
| `created_at` | datetime | 创建时间。 |
| `updated_at` | datetime | 更新时间。 |

唯一约束：

```text
(user_id, platform, platform_note_id)
```

这样同一个用户下，同一平台笔记只会被记录一次废弃状态。

## 5. 废弃原因编码

第一版使用固定原因码，不引入规则引擎。

| 原因码 | 说明 |
| --- | --- |
| `geo` | GEO / SEO-GEO / AI 搜索优化相关，当前运营目标不需要。 |
| `square_wall_bathtub` | 方形浴缸、贴墙浴缸、方形贴墙浴缸相关。 |
| `low_score_non_bathtub` | 非浴缸相关且评分低于阈值。 |
| `low_score_bathtub` | 浴缸相关但评分低于阈值。 |
| `manual_excluded` | 人工指定排除。 |

本次用户选择“严格清理”，评分阈值为 `< 7`。

## 6. 内容库行为

### 6.1 默认列表

内容库查询默认排除命中 `note_exclusions` 的小红书笔记。

判断条件：

```text
notes.user_id = note_exclusions.user_id
notes.platform = note_exclusions.platform
notes.note_id = note_exclusions.platform_note_id
```

用户影响：打开内容库时，已废弃内容不再干扰日常选题和改写。

### 6.2 可见性和历史数据

内容库保留三种可见性：

| 可见性 | 行为 | 用户影响 |
| --- | --- | --- |
| `active` | 默认只看未命中 `note_exclusions` 的可用内容。 | 日常选题和改写不被废弃内容干扰。 |
| `all` | 同时展示可用内容和废弃内容。 | 运营需要复查废弃判断时不用进数据库。 |
| `excluded` | 只展示命中 `note_exclusions` 的废弃内容。 | 可集中审计被清理内容。 |

数据库仍保留原 note 和分析结果，便于后续审计、恢复或开发更完整的废弃库 UI。

### 6.3 飞书分析状态筛选

内容库分析状态筛选支持虚拟状态 `未分析`。该状态不要求写入 `note_analysis_results.analysis_status`，而是由系统根据“没有飞书分析结果，或分析结果缺少有效分析字段/评分”动态判定。

用户影响：运营可以单独筛出尚未完成飞书分析的信息，等待飞书公式或人工分析完成后再回传，不会和已完成分析内容混在一起。

### 6.4 物理删除入口

现有 `DELETE /notes/{note_id}` 继续保留，但本次清理不使用它作为默认动作。新的废弃动作应使用专门接口，避免误把“清理内容库”实现成不可追溯删除。

## 7. 采集与入库拦截

在小红书笔记保存或 upsert 前增加排除检查。

输入：

```text
user_id, platform='xhs', platform_note_id
```

如果命中 `note_exclusions`：

1. 不创建新 note。
2. 不更新已有被排除 note 的内容。
3. 不进入飞书同步队列。
4. 不触发分析。
5. 返回或记录 skipped 状态，原因来自 `note_exclusions.reason_code`。

如果未命中：按现有流程保存。

## 8. 飞书同步行为

第一版不删除飞书记录，也不新增复杂系统控制字段。飞书侧只复用现有 `分析状态` 字段，新增一个状态选项：`已废弃`。

字段规则：

| 飞书字段 | 更新值 | 说明 |
| --- | --- | --- |
| `分析状态` | `已废弃` | 让飞书公式、视图和人工协作都能识别该行不用继续分析。 |
| `内容利用方式` | `废弃` | 可选同步，用于已有筛选逻辑；不作为唯一流程控制依据。 |
| `分析备注` | 追加 `系统已废弃：<reason_text>` | 保留废弃原因，便于复查。 |

飞书公式自动更新应以 `分析状态 != 已废弃` 作为前置条件。也就是说，用户开启自动更新前，需要让公式遇到 `已废弃` 时直接跳过或保持空值，避免继续消耗分析资源。

若飞书记录 ID 不存在或飞书 API 不可用：

- 本地废弃动作仍可成功。
- 返回结果中明确列出飞书同步失败项。
- 不阻塞内容库默认隐藏和采集拦截。

## 9. 批量清理服务

新增后端服务方法，输入 note IDs 或规则参数，输出处理结果。

第一版支持两类入口：

1. `mark_notes_excluded(note_ids, reason_code, reason_text)`：按明确 note ID 标记。
2. `build_current_cleanup_candidates(strict=True)`：根据本次规则生成候选清单，供执行脚本或接口使用。

本次规则：

```text
候选 = GEO 相关
    OR 方形/贴墙浴缸相关
    OR 非浴缸且 score < 7
    OR 浴缸相关且 score < 7
```

其中“浴缸相关”用标题、正文、飞书主题对象、核心观点、结构分析等字段中的关键词判断；“GEO 相关”和“方形/贴墙浴缸相关”优先级高于评分。

## 10. API 设计

第一版新增后端 API：

```text
POST /api/notes/exclusions/mark
```

请求：

```json
{
  "note_ids": [1, 2, 3],
  "reason_code": "low_score_bathtub",
  "reason_text": "浴缸相关但评分低于 7，按严格清理规则废弃",
  "sync_feishu": true
}
```

响应：

```json
{
  "excluded_count": 3,
  "skipped_count": 0,
  "feishu_updated_count": 2,
  "feishu_failed_count": 1,
  "errors": []
}
```

权限：只能操作当前用户自己的 notes。

## 11. 验证标准

完成后必须验证：

1. 标记废弃后，`note_exclusions` 中有对应记录。
2. 内容库默认查询不再返回已废弃 note。
3. 再次保存相同 `platform_note_id` 时被跳过，不重新入库。
4. 飞书有 `external_record_id` 的记录被标记为废弃；失败时返回明确错误。
5. 当前这批 GEO、方形/贴墙浴缸、低分候选可以被批量标记。
6. 后端相关测试通过。

## 12. 飞书表配置要求

飞书表不新增复杂控制字段，只要求现有 `分析状态` 字段支持 `已废弃` 选项。

系统侧 `ensure-fields` 需要保证 `分析状态` 的选项包含：

```text
待分析、分析中、已完成、已废弃
```

如果旧表已经存在 `完成分析`、`未完成分析` 这类人工选项，系统应兼容读取，但新增废弃状态统一写 `已废弃`。用户在飞书公式中只需要加一个简单前置条件：

```text
如果 分析状态 = 已废弃：跳过分析
否则：执行原公式
```

## 13. 用户体验原则

这次改动对用户的核心影响是：清理不是“删掉看不见”，而是“系统记住不要再浪费资源”。

用户默认看到的是干净内容库；系统背后保留负样本，用于后续防重复、防污染、防 token 浪费。
