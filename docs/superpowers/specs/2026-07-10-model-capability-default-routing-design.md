# 管理员统一模型能力路由设计

## 背景

当前 `model_configs.is_default` 只能表达“文本模型默认”或“图片模型默认”，但图片模型实际承担两种不同能力：图片理解与图片生成。

当管理员默认图片模型只支持图片理解时，图片生成流程会跳过该配置，再从所有管理员图片配置中按 `is_default DESC, id ASC` 选择第一个兼容 Provider。这个隐式回退会把历史配置、测试配置或失效配置选为生产默认。本次故障即由此触发：图片生成选择了旧的 OpenAI-compatible 配置，而不是此前可用的 RunningHub 配置，随后上游返回 401。

## 目标

- 由管理员为全系统统一指定文本生成、图片理解、图片生成三个默认模型。
- 运行时按能力精确选择模型，不再按配置创建顺序猜测。
- 默认绑定缺失、失效或能力不兼容时失败关闭，不静默回退。
- 普通用户继续使用管理员统一配置，不能查看密钥或修改路由。
- 绑定模型被修改、删除或失效时给管理员明确的修复入口。
- 保持现有模型连接信息与密钥加密方式不变。

## 非目标

- 不增加用户级、租户级或平台级模型覆盖。
- 不重构 Provider 客户端或 XHS SDK。
- 不自动重试 401、切换备用供应商或重新提交付费生成。
- 不在本轮引入多级候选、权重、负载均衡或自动故障转移。
- 不在迁移中凭配置 ID 或 Provider 名称猜测图片生成默认模型。

## 方案决策

新增系统级能力绑定表 `model_capability_defaults`，将模型连接信息与默认路由职责拆开。

能力值沿用现有服务层命名：

| capability | 管理员界面名称 | 主要调用场景 |
| --- | --- | --- |
| `text` | 文本生成 | 改写、润色、草稿、分析文本 |
| `vision` | 图片理解 | 图片描述、图片内容理解 |
| `image_generation` | 图片生成 | 文生图、参考图生图、封面生成 |

不采用以下方案：

- 在 `model_configs` 上增加三个默认布尔字段：能力继续耦合在连接配置上，每增加能力都要改表。
- 使用 JSON 保存映射：缺少外键、唯一性和删除保护，容易产生悬空配置。

## 数据模型

新增 SQLAlchemy 模型 `ModelCapabilityDefault`：

| 字段 | 约束 | 含义 |
| --- | --- | --- |
| `id` | 主键 | 记录 ID |
| `capability` | 唯一、非空 | `text`、`vision`、`image_generation` |
| `model_config_id` | 外键、非空 | 指向 `model_configs.id` |
| `updated_by_user_id` | 外键、非空 | 最近设置该路由的管理员 |
| `created_at` | 非空 | 创建时间 |
| `updated_at` | 非空 | 最近更新时间 |

系统范围内每种能力最多一条绑定。绑定模型删除采用应用层保护：如果仍被能力路由引用，删除 API 返回 409，并提示先切换对应能力。数据库外键使用限制删除，防止绕过 API 产生悬空记录。

`model_configs.is_default` 在兼容期保留，但新运行时和新管理页不再读取或写入它。后续独立迁移再删除该字段，本轮不扩大数据库变更范围。

## 能力兼容规则

服务层保留单一能力判定入口，绑定写入和运行时读取都调用同一规则：

- `text`：`model_type == "text"`。
- `vision`：`model_type == "image"` 且 Provider 属于视觉理解能力集合。
- `image_generation`：`model_type == "image"` 且 Provider 属于图片生成能力集合。

Provider 集合只用于拒绝明显不兼容的绑定，不用于自动选择默认模型。OpenAI-compatible 是否真的支持对应接口，仍由能力对应的连接测试和真实上游响应决定。

## 路由服务

将 `get_default_model_config` 的隐式扫描替换为显式能力解析：

1. 使用 capability 查询 `model_capability_defaults`。
2. 加载绑定的 `ModelConfig`。
3. 校验配置所有者是状态正常的管理员。
4. 校验配置与 capability 兼容。
5. 校验 Base URL、模型名和加密密钥均存在，并解密密钥。
6. 返回唯一的模型配置和密钥。

任何步骤失败都不扫描其他管理员配置：

- 未绑定：返回 `MODEL_CAPABILITY_DEFAULT_NOT_CONFIGURED`。
- 绑定不存在或管理员失效：返回 `MODEL_CAPABILITY_DEFAULT_INVALID`。
- 能力不兼容：返回 `MODEL_CAPABILITY_DEFAULT_INCOMPATIBLE`。
- 密钥或连接字段缺失：返回 `MODEL_CAPABILITY_DEFAULT_INCOMPLETE`。

模型选择发生在积分预留和并发租约之前，因此配置错误不会扣分，也不会占用图片生成并发槽位。

## 管理 API

新增管理员接口：

- `GET /api/model-configs/capability-defaults`
  - 返回三个能力的当前绑定、模型摘要、兼容状态和修复提示。
- `PUT /api/model-configs/capability-defaults/{capability}`
  - 请求体：`{"model_config_id": <id>}`。
  - 校验管理员拥有该模型配置、能力兼容且必要连接字段齐全。
  - 原子新增或替换能力绑定。

调整现有接口：

- `GET /api/model-configs` 为每个配置返回 `supported_capabilities` 和 `assigned_capabilities`。
- `POST /api/model-configs/{id}/test` 接受明确的 `capability` 参数，并按对应真实调用路径测试。
- 图片生成测试必须调用图片生成鉴权路径，而不能继续用图片理解的 `/chat/completions` 代替；界面明确提示该测试可能消耗上游额度。
- `DELETE /api/model-configs/{id}` 在配置被绑定时返回 409。
- `POST /api/model-configs/{id}/set-default` 标记为兼容接口，不再被新前端调用；运行时不读取其结果。

普通用户访问能力绑定或模型配置管理接口继续返回权限错误。

## 管理页交互

模型配置页采用“先路由、后连接配置”的信息层级。

页面顶部新增“能力路由”区域，固定展示三个路由槽位：

- 文本生成
- 图片理解
- 图片生成

每个槽位显示当前模型、Provider、最近测试状态和“更换模型”操作。下拉选择只展示明显兼容的配置；未绑定或绑定失效时显示红色状态和直接修复入口。

模型配置卡片继续负责连接信息的新增、编辑、测试和删除，但移除“设为该类型默认模型”按钮与表单中的 `is_default` 复选框。卡片改为展示“用于：文本生成 / 图片理解 / 图片生成”标签。

管理员操作路径为：

1. 新增或编辑模型连接。
2. 选择要测试的能力并执行连接测试。
3. 在能力路由区域选择该模型。
4. 保存后立即刷新路由状态。

本轮沿用现有 Ant Design 深色后台视觉，不做无关页面重设计。桌面端三个能力槽位并排，窄屏改为单列；错误、加载、空配置和权限状态都必须可读。

## 数据迁移

Alembic 新增 `model_capability_defaults` 表并执行保守回填：

- `text`：仅当存在唯一、兼容且当前默认的管理员文本配置时回填。
- `vision`：仅当存在唯一、兼容且当前默认的管理员图片配置时回填。
- `image_generation`：只有存在唯一兼容候选时回填；多个候选时保持未配置，要求管理员显式选择。

迁移不得根据最小 ID、最近 ID 或 Provider 优先级选择图片生成模型。

当前真实数据库存在多个图片生成兼容候选，因此迁移后应由管理员在新页面显式将 RunningHub 配置绑定为“图片生成”。在完成绑定前，图片生成请求应返回明确的未配置错误，而不是调用旧配置。

## 错误与安全

- 对普通用户隐藏 API Key、完整上游错误正文和供应商内部 URL。
- 普通用户看到可执行提示，例如“图片生成模型暂不可用，请联系管理员检查模型配置”。
- 管理员在任务详情或模型测试结果中看到模型配置 ID、Provider、HTTP 状态和经过脱敏的错误摘要。
- 401 不自动重试，不自动切换其他模型，避免重复计费。
- 能力路由更新记录 `updated_by_user_id` 和时间，便于追查配置变化。

## 测试与验收

### 后端

- 视觉默认与图片生成默认可同时绑定到不同模型。
- 存在更小 ID 的旧 OpenAI-compatible 配置时，图片生成仍只使用显式绑定的 RunningHub 配置。
- 未绑定、悬空、非管理员所有、能力不兼容和字段不完整分别返回稳定错误码。
- 路由失败发生在积分预留和并发租约之前。
- 普通用户不能读取或修改能力绑定。
- 删除已绑定配置返回 409；切换绑定后可以删除旧配置。
- 能力测试走对应接口；图片生成测试不再复用视觉理解测试。
- Alembic 迁移只有在候选唯一时回填，不按 ID 猜测。

### 前端

- 管理员一眼看到三个能力当前分别使用哪个模型。
- 管理员可以完成新增配置、能力测试、绑定和切换。
- 模型卡片不再出现含糊的“该类型默认”入口。
- 未配置、绑定失效、测试失败、加载中和空配置状态有明确下一步。
- 桌面与移动视口无横向溢出，核心操作可点击并产生真实状态变化。

### 回归验证

- 运行模型配置、AI 文本、图片理解、同步与异步图片生成相关后端测试。
- 运行 Alembic 单头检查和升级测试。
- 运行前端测试与生产构建。
- 使用模拟 Provider 验证，不在开发验收中调用真实付费图片生成。
- 根目录标准服务只有在用户单独授权重启后，才进行 `18080/18081` 运行态验证。

## 交付边界

- 实现与验证仅修改模型配置、能力路由、相关管理页和测试。
- 不修改 XHS SDK、签名层、发布策略或真实账号行为。
- 不自动 commit、push、重启根目录服务或执行真实付费生成。
