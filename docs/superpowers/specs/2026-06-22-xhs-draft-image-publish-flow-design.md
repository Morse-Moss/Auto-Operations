# XHS 草稿-图片工坊-发布链路优化设计

日期：2026-06-22

## 1. 背景

运营反馈集中在 4 个问题：

1. 草稿工坊里的草稿不能命名，多个草稿和版本不方便管理。
2. 草稿工坊润色完内容后，不能把原图和改写后的文字顺畅传到图片工坊；运营需要把案例图中的产品替换成自己的产品图。
3. 自动运营生成的正文有格式符号，需要手动删除。
4. 自动运营生成内容时，标题字段有标题，正文开头又重复一个标题，需要手动删除。

本设计采用“完整运营链路优化 + 复用现有图生图能力”。目标是让运营按“写文案 → 做图 → 发布”的自然流程工作，而不是在草稿、图片工坊、发布中心之间复制粘贴。

## 2. 目标

### 2.1 用户目标

- 运营可以用内部草稿名管理多个草稿和版本，不污染小红书发布标题。
- 草稿内容可以一键进入图片工坊，自动带上标题、正文、标签和案例图候选。
- 图片工坊可以复用现有图生图能力，基于案例图和产品图生成替换图。
- 图生图结果可以带着草稿文案进入发布中心。
- 不需要做图的内容仍然可以从草稿工坊直接进入发布中心。
- AI 自动生成或改写内容进入草稿/发布前，正文应尽量干净，不重复标题，不保留明显 Markdown/格式符号。

### 2.2 系统目标

- 手术式扩展现有 FastAPI/React/SQLAlchemy 主系统，不重构成全新 pipeline 引擎。
- 后端统一承担 AI 内容规范化，避免不同入口清洗规则不一致。
- 前端轻量传递草稿到图片工坊的上下文，优先不新增复杂 workflow 表。
- 保留现有发布中心和图片工坊能力边界，不修改 XHS SDK、签名、真实发布策略。

## 3. 非目标

本轮不做：

- 不新增第三方图生图模型。
- 不改变现有图片工坊底层生成接口，优先复用现有图生图能力。
- 不改造 XHS SDK、签名、真实发布策略。
- 不做真实账号自动发布增强。
- 不把草稿、图片工坊、发布中心重构成完整工作流引擎。
- 不接入 legacy TypeScript 系统能力。

## 4. 总体链路

目标链路：

```text
内容来源 / 自动运营
  → 草稿工坊：可命名、可编辑、AI 内容已清洗
  → 图片工坊：带着草稿文案 + 案例图进入图生图
  → 发布中心：带着最终图文进入发布编辑
```

同时保留直达路径：

```text
草稿工坊 → 发布中心
```

适用于纯文字内容、已有自有图片、不需要图生图处理的内容。

## 5. 数据模型设计

### 5.1 草稿内部名称

在草稿模型中新增字段：

```text
draft_name: string | null
```

含义：运营内部管理名，不发到小红书。

现有 `title` 保持为小红书发布标题。

展示规则：

```text
草稿列表主标题 = draft_name || title || "未命名草稿"
草稿列表副标题 = title + 创建时间 / 来源信息
发布中心标题 = title
```

复制草稿时复制 `draft_name`，并建议自动追加“副本”。例如：

```text
浴缸案例图替换 → 浴缸案例图替换 副本
```

### 5.2 草稿图片来源

进入图片工坊时，案例图候选来源优先级：

1. 草稿已绑定图片资产。
2. 来源笔记图片。
3. 用户手动上传或选择图片。

如果没有任何候选图，不阻断进入图片工坊，图片工坊提示上传案例图。

## 6. 接口设计

### 6.1 草稿创建/更新

草稿创建和更新接口扩展支持：

```text
draft_name
title
body
tags
```

规则：

- `draft_name` 可为空。
- 空字符串按未命名处理。
- 后端返回草稿时统一带上 `draft_name`。
- 发布中心只使用 `title` 作为发布标题，不使用 `draft_name`。

### 6.2 AI 内容规范化服务

新增后端纯函数/服务：

```python
normalize_xhs_generated_content(title: str, body: str, tags: list) -> NormalizedContent
```

输出包含：

```text
title
body
tags
warnings?
```

使用位置：

```text
自动运营生成 → normalize → 草稿
AI 改写生成 → normalize → 草稿候选
发布前保存/送入发布中心 → normalize 兜底
```

### 6.3 图片工坊草稿上下文

前端传递轻量上下文，优先使用路由 state 或 sessionStorage：

```ts
type ImageStudioDraftContext = {
  source: "draft";
  draft_id: number;
  draft_name?: string | null;
  title: string;
  body: string;
  tags: Array<{ name?: string; value?: string }>;
  source_note_id?: number | null;
  candidate_images: Array<{
    id?: number;
    url?: string;
    local_path?: string;
    source: "draft_asset" | "source_note" | "manual";
  }>;
};
```

图片工坊接收上下文后进入“从草稿继续制作”状态。

### 6.4 图片工坊到发布中心

图片工坊生成结果送入发布中心时传递：

```text
title
body
tags
image_asset_ids / generated_image_urls
source_draft_id
```

发布中心只负责最终图文编辑、检查和发布准备，不需要知道图片生成过程。

## 7. AI 内容清洗规则

### 7.1 删除正文重复标题

处理示例：

```text
title = "卫生间浴缸怎么选？看完少踩 3 个坑"
body = "卫生间浴缸怎么选？看完少踩 3 个坑\n\n很多人装修卫生间..."
```

输出：

```text
body = "很多人装修卫生间..."
```

也处理以下正文首行形式：

```text
# 卫生间浴缸怎么选？看完少踩 3 个坑
标题：卫生间浴缸怎么选？看完少踩 3 个坑
《卫生间浴缸怎么选？看完少踩 3 个坑》
```

### 7.2 清理 Markdown/格式符号

输入：

```text
## 开头
**浴缸选购重点**
- 尺寸
- 材质
```

输出倾向：

```text
开头
浴缸选购重点
尺寸
材质
```

保留可读分段，不强行压成一行。

### 7.3 清理说明性前缀

清理正文开头的：

```text
正文：
内容：
以下是适合小红书发布的内容：
小红书文案：
```

### 7.4 标签处理

标签只做轻度规范：

- 去掉空值。
- 去掉重复。
- 保持当前系统对 `#` 的约定。
- 不凭空生成新标签。

## 8. 前端交互设计

### 8.1 草稿工坊字段

草稿编辑区顶部展示两个字段：

```text
内部草稿名：浴缸案例图替换 - 0622 A版
发布标题：卫生间浴缸怎么选？看完少踩 3 个坑
```

草稿列表主标题优先显示内部草稿名；发布中心仍使用发布标题。

### 8.2 草稿工坊操作按钮

按钮按目标分组：

```text
保存草稿

下一步：
[送入图片工坊] [送入发布中心]

辅助：
[复制草稿] [删除草稿] [发布前检查]
```

点击“送入图片工坊”：

1. 自动保存当前草稿。
2. 收集草稿文案和图片候选。
3. 跳转图片工坊。
4. 图片工坊显示“来自草稿”。

点击“送入发布中心”：

1. 自动保存当前草稿。
2. 清洗标题/正文。
3. 跳转发布中心。
4. 发布中心加载当前图文。

### 8.3 图片工坊草稿上下文卡片

如果带草稿上下文进入图片工坊，顶部显示：

```text
来自草稿：浴缸案例图替换 - 0622 A版
发布标题：卫生间浴缸怎么选？看完少踩 3 个坑

[查看正文] [回到草稿]
```

正文默认折叠，避免占用图片操作区域。

### 8.4 案例图候选区

图片工坊显示案例图候选：

```text
案例图
系统已从草稿/来源笔记带入 6 张图片，选择一张作为图生图参考。

[图1] [图2] [图3] [图4] ...
[上传案例图]
```

如果没有候选图：

```text
这个草稿还没有案例图。请上传一张案例图，作为图生图参考。
[上传案例图]
```

### 8.5 产品图上传区

图片工坊提供产品图上传：

```text
产品图
上传你自己的产品图，用于替换案例图中的同类产品。

[上传产品图]
```

案例图和产品图都准备后，启用：

```text
[生成替换图]
```

生成完成后展示：

```text
生成结果
[结果图1] [结果图2]

[加入发布素材] [重新生成] [送入发布中心]
```

## 9. 错误兜底

### 9.1 草稿没有内部名

不报错，显示“未命名草稿”。

### 9.2 草稿没有来源图片

不阻断“送入图片工坊”，图片工坊提示上传案例图。

### 9.3 来源笔记图片无法解析

不阻断流程，只提示：

```text
未找到来源案例图，可手动上传案例图继续。
```

### 9.4 图生图失败

不丢失草稿上下文，保留：

- 当前草稿文案。
- 已选案例图。
- 已上传产品图。
- 错误提示。

提示文案：

```text
生成失败，草稿内容和已选图片已保留。请调整图片或稍后重试。
```

### 9.5 发布中心缺少图片

允许纯文字路径继续，除非当前平台发布规则强制要求图片。若强制要求，则提示：

```text
当前发布方式需要至少 1 张图片。请返回图片工坊生成或上传图片。
```

## 10. 数据一致性

点击“送入图片工坊”或“送入发布中心”前，前端必须先保存草稿。

流程：

```text
点击下一步
  → save draft
  → normalize if needed
  → collect context
  → navigate
```

图片生成结果不直接覆盖草稿原图。它作为生成结果存在，用户点击“加入发布素材”或“送入发布中心”后才成为发布素材。

## 11. 验证标准

### 11.1 草稿命名

操作：

1. 新建草稿。
2. 填内部草稿名。
3. 填发布标题。
4. 保存。
5. 刷新页面。

通过标准：

- 列表主标题显示内部草稿名。
- 编辑区发布标题仍是发布标题。
- 内部草稿名不进入发布标题。

### 11.2 自动运营正文重复标题

输入：

```text
title: "SaaS 工具怎么选？"
body:
"SaaS 工具怎么选？\n\n正文第一段..."
```

通过标准：

- 保存后的正文不再重复标题。
- 标题字段仍保留。

### 11.3 格式符号清洗

输入：

```text
# 标题
**重点**
- 第一条
- 第二条
```

通过标准：

- 正文没有 `#`、`**`、无意义 bullet 符号。
- 分段仍可读。

### 11.4 草稿带来源图进入图片工坊

操作：

1. 从有图片的来源笔记创建草稿。
2. 点击“送入图片工坊”。

通过标准：

- 图片工坊显示“来自草稿”。
- 标题、正文、标签被带入。
- 案例图候选自动展示。

### 11.5 草稿无图进入图片工坊

操作：

1. 创建纯文字草稿。
2. 点击“送入图片工坊”。

通过标准：

- 不报错。
- 图片工坊提示上传案例图。
- 草稿文案仍被带入。

### 11.6 图片工坊图生图后送入发布中心

操作：

1. 选择案例图。
2. 上传产品图。
3. 生成图生图结果。
4. 点击送入发布中心。

通过标准：

- 发布中心拿到清洗后的标题、正文、标签。
- 发布中心拿到生成图片。
- 来源草稿 ID 保留。

## 12. 测试建议

后端：

- AI 清洗函数单元测试。
- 草稿 create/update 返回 `draft_name`。
- 复制草稿处理 `draft_name`。
- send-to-publish 不污染标题/正文。

前端：

- 前端 build。
- 手动跑通草稿 → 图片工坊 → 发布中心。
- 若本地 webapp 测试工具可用，补一条端到端冒烟验证。

## 13. 实施分阶段建议

建议分三步实现：

1. 内容质量底座：`draft_name` + AI 内容规范化。
2. 草稿到图片工坊：上下文传递 + 案例图候选。
3. 图片工坊到发布中心：图生图结果携带草稿文案进入发布编辑。

这样每一步都能独立验证，并且不会把真实发布、XHS SDK、图片模型接入混进本轮改动。
